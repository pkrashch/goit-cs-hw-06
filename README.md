# goit-cs-hw-06. Вебзастосунок з HTTP- та Socket-серверами, MongoDB

Найпростіший вебдодаток на Python без використання вебфреймворків.
Один файл `main.py` запускає два процеси (`multiprocessing.Process`):

- **HTTP-сервер** (`http.server`, порт `3000`) — маршрутизація для
  `index.html` та `message.html`, віддача статичних ресурсів (`style.css`,
  `logo.png`), 404 → `error.html`, прийом даних форми (`POST /message`).
- **Socket-сервер** (UDP, порт `5000`) — приймає від HTTP-сервера сирий
  байт-рядок з даними форми, перетворює його на словник і зберігає
  документ у MongoDB.

HTTP-сервер не звертається до MongoDB напряму: отримавши `POST /message`,
він пересилає дані форми Socket-серверу по UDP, а Socket-сервер вже сам
перетворює їх на словник і робить запис у базу — так, як вимагає завдання.

Формат документа в MongoDB:

```json
{
    "date": "2026-09-21 09:25:31.311493",
    "username": "polina",
    "message": "Привіт з тесту!"
}
```

Поле `date` — це час отримання повідомлення Socket-сервером
(`datetime.now()`), кожне нове повідомлення дописується окремим документом.

## Структура проєкту

```
goit-cs-hw-06/
├── main.py              # HTTP-сервер + Socket-сервер (два процеси)
├── index.html
├── message.html
├── error.html            # сторінка 404
├── style.css
├── logo.png
├── requirements.txt
├── Dockerfile
├── docker-compose.yaml   # app + mongodb, volume для персистентності даних
└── .dockerignore
```

## Запуск через Docker Compose (рекомендовано)

```
docker-compose up --build
```

- Вебдодаток буде доступний на http://localhost:3000
- MongoDB підніметься автоматично поруч (сервіс `mongodb`, порт `27017`)
- Дані MongoDB зберігаються в іменованому volume `mongo_data`, тобто
  живуть поза контейнером і не втрачаються при перестворенні контейнера
  (`docker-compose down` без `-v` дані не видаляє)

Щоб зупинити:

```
docker-compose down
```

## Запуск без Docker (локально)

Потрібен локально запущений MongoDB на `localhost:27017` (або свій
`MONGO_URI` в змінних середовища).

```
pip install -r requirements.txt
python3 main.py
```

Вебдодаток буде на http://localhost:3000, Socket-сервер слухає UDP-порт
`5000` (використовується лише для внутрішньої комунікації між HTTP- та
Socket-сервером, ззовні звертатись до нього не потрібно).

## Перевірка роботи

1. Відкрити http://localhost:3000/ — головна сторінка.
2. Перейти на http://localhost:3000/message.html, заповнити форму
   (ім'я користувача + повідомлення) і натиснути «Надіслати».
3. Після відправки форми браузер перенаправляється назад на
   `/message.html`, а сам документ уже записаний у MongoDB — перевірити
   можна, наприклад, через `mongosh`:

   ```
   docker exec -it goit-cs-hw-06-mongo mongosh messages_db --eval "db.messages.find().pretty()"
   ```

4. Неіснуючий маршрут (наприклад, http://localhost:3000/foo) повертає
   сторінку `error.html` зі статусом `404`.

Я перевірила логіку HTTP-маршрутизації (усі статичні сторінки й ресурси,
404 → `error.html`), пересилання даних форми по UDP та збереження
документа очікуваного формату в MongoDB — end-to-end тестом (HTTP-запити
до всіх маршрутів + відправка форми + перевірка збереженого документа).
Сам `docker-compose up` у середовищі розробки перевірити не було
можливості (немає доступу до Docker-демона), тому перед фінальною
відправкою варто самостійно прогнати `docker-compose up --build` і
переконатись, що обидва контейнери піднімаються та вебдодаток відповідає
на http://localhost:3000.
